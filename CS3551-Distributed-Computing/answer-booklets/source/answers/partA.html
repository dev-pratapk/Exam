Motivations for distributed systems. They are built to achieve: (i) resource sharing — files, printers, databases and services used by many users; (ii) communication and collaboration — e-mail, chat, distributed databases; (iii) scalability — add nodes to handle growing load; (iv) fault tolerance and reliability — replication keeps the service alive after a failure; (v) cost and performance — many cheap machines give better price/performance than one supercomputer; (vi) geographic distribution and load sharing; (vii) transparency — remote resources are accessed as if local.

Scalar time keeps one integer Li per process (Lamport clock). R1: Li := Li + 1 before each event. R2: a message carries Li as timestamp t; on receipt, Li := max(Li, t) + 1. Hence a → b ⇒ L(a) < L(b), but not conversely.

Vector time keeps Vi[1..n], where Vi[j] counts the events of Pj known to Pi. R1: Vi[i] := Vi[i] + 1 before an event. R2: on receiving (m, t), Vi[j] := max(Vi[j], t[j]) ∀j, then Vi[i] := Vi[i] + 1. Hence a → b ⇔ V(a) < V(b).

Global state: the collection of the local states of all processes and the states of all channels (messages in transit).

Consistent global state: one that can occur in some execution, i.e. it satisfies C1 — every received message was sent earlier, receive(m) ∈ LSj ⇒ send(m) ∈ LSi; and C2 — every sent but unreceived message is recorded in the channel, send(m) ∈ LSi ∧ receive(m) ∉ LSj ⇒ m ∈ SCij.

Three requirements of mutual exclusion algorithms.

  1. Safety (mutual exclusion): at most one process is inside the critical section (CS) at any time.
  2. Liveness (progress): a process that requests entry eventually enters the CS; requests are not blocked forever (no deadlock).
  3. Fairness (bounded waiting): no process starves; a waiting request is not overtaken indefinitely, and requests are normally granted in the order made.

False (phantom) deadlock. A false deadlock is reported by a deadlock detection algorithm when no real deadlock exists — the detector observes a cycle in the wait-for graph that has already been broken.

When it occurs. It occurs because detection works on stale or inconsistent state information: probe or wait-for messages are delayed, a process releases the resource or aborts after sending its reply, or cycles are combined from different instants. Message delays and the absence of a global clock make the collected wait-for graph inconsistent. Consistent snapshots, timestamps and two-phase detection reduce false deadlocks.

Four issues in failure recovery.

  • Domino effect: rolling back one process may force dependent processes to roll back, possibly to the very beginning.
  • Orphan processes: processes that continue running after the failure of a process on which they depend.
  • Lost in-transit messages: messages sent before the failure but not yet received must be replayed or the recovered state made consistent.
  • Checkpoint overhead and garbage collection: frequent checkpoints cost time and stable storage; obsolete checkpoints must be identified and deleted, and repeated failures during recovery must be handled.

Checkpoint. A checkpoint is a snapshot of a process's local state — memory, registers, program counter and open files — saved periodically on stable (non-volatile) storage; the messages it sends and receives are kept in a message log.

Usefulness. On failure the process restarts from its latest checkpoint instead of from the beginning, so only the work done after that checkpoint is lost. Checkpoints of all processes, together with message logs, are used to compute a recovery line — a consistent global state — so the system can roll back and resume correctly. They reduce recomputation, limit recovery time and make transient failures tolerable.

Virtualization is the technique of abstracting physical computing resources (CPU, memory, storage, network) and presenting them as multiple isolated virtual resources. A hypervisor (VMM) runs on the host and creates virtual machines, each with its own guest OS, on one physical machine.

It decouples software from hardware, gives isolation and multi-tenancy, allows over-commitment of resources, live migration and rapid creation of instances. In cloud computing it is the basis of IaaS and PaaS: providers sell virtual machines and containers instead of physical servers, improving utilization and elasticity.

Characteristics of cloud computing (NIST):

  1. On-demand self-service — a user provisions computing resources automatically, without human interaction with the provider.
  2. Broad network access — services are available over the network through standard devices such as laptops and mobiles.
  3. Resource pooling — the provider's resources are pooled to serve many tenants (multi-tenancy), with location independence.
  4. Rapid elasticity — resources can be scaled out and in quickly and appear unlimited to the user.
  5. Measured service — usage is monitored, controlled and billed, giving pay-per-use.

These give scalability, cost saving, reliability and location independence.
