Given and aim

Deadlock is analysed on the Wait-For Graph (WFG): Pi → Pj means Pi is blocked waiting for a resource held by Pj. The two Chandy–Misra–Haas (CMH) algorithms differ only in the request model: AND (wait for all) and OR (wait for any one).

1. AND model and OR model

  • AND model: a process needs every resource it requested; a directed cycle in the WFG is necessary and sufficient for deadlock (Fig. 1).
  • OR model: a process needs any one requested resource, so a cycle alone is not enough. Deadlock needs a knot — a set S of blocked processes whose every outgoing edge stays inside S (Fig. 2).

2. CMH algorithm for the AND model

Message and data. The only message is probe(i, j, k): a detection initiated by Pi, forwarded by Pj (a blocked process dependent on Pi) to Pk, the process Pj waits for — so i = initiator, j = sender, k = receiver. Each Pi keeps a Boolean array dependenti, true at dependenti(j) once a probe of initiator j has passed through Pi (initially false); it stops a branch being explored twice. A blocked process stays blocked during detection.

  1. If Pi is locally dependent on itself (a blocked cycle at its own site), declare deadlock.
  2. Otherwise send probe(i, j, k) to Pk for every WFG edge Pj → Pk leaving the set of processes dependent on Pi.
  3. On probe(i, j, k) at Pk: if Pk is blocked, dependentk(i) is false and Pk has not replied to all requests of Pj, set dependentk(i) = true. If k = i, declare Pi deadlocked; else forward probe(i, m, n) on every edge leaving Pk. Otherwise discard.
Deadlock at Pi ⇔ it receives probe(i, j, i) (receiver = initiator)

Example (Fig. 1). P1 sends probe(1,1,2); P2 forwards probe(1,2,3); P3 forwards probe(1,3,1) to P1 — receiver = initiator → deadlock.

Performance. One probe per WFG edge; for m processes over n sites at most m(n-1)/2 fixed-size messages, and delay O(n).

3. CMH algorithm for the OR model

Messages and data. A diffusion computation uses query(i, j, k) and reply(i, j, k), both initiated by Pi and sent from Pj to Pk. For initiator Pi, process Pk keeps numk(i) = queries sent out, and waitk(i) = true while Pk has been continuously blocked since the engaging query. DSk is the dependent set of Pk.

Engaging query. The first query of initiator Pi to reach a blocked Pk; only it is propagated, giving one forward wave per initiator.

  1. Blocked Pi sends query(i, i, j) to every Pj ∈ DSi, setting numi(i) = |DSi|, waiti(i) = true.
  2. On query(i, j, k) at Pk: if Pk is executing, discard. If engaging, set waitk(i) = true, send query(i, k, m) to every Pm ∈ DSk, set numk(i) = |DSk|; if non-engaging and waitk(i), send reply(i, k, j) to Pj.
  3. On reply(i, j, k) at Pk: if waitk(i), decrement numk(i); at 0, if k = i declare deadlock, else reply to the engager.
  4. A process replies to its engaging query only after replies to all queries it forwarded.
Deadlock at Pi ⇔ numi(i) = 0 (replies to all its queries)

Example (Fig. 2). Every reached process in the knot is blocked, so none replies early; replies ripple back and when P1 has all replies, num1(1) = 0 → deadlock.

Performance. For e WFG edges, at most e queries and e replies = 2e messages, delay O(n); waitk(i) rejects stale replies, so no false deadlock.

Conclusion

Both chase WFG edges and are exact if the graph is static during detection. The AND version uses one probe message, detects a cycle when probe(i, j, i) returns to its initiator, and costs at most m(n-1)/2 messages with O(n) delay. The OR version is a diffusion computation with query and reply, detects a knot when the initiator has replies to all its queries, and costs 2e messages (e queries + e replies).
