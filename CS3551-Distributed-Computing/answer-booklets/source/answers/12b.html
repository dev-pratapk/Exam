Introduction

Events in a distributed system must be ordered or timed even though there is no common clock. Two approaches exist: physical clock synchronization, which keeps the real-time clocks of machines close to each other, and logical clocks, which capture only the causal order of events.

1. Physical clock synchronization

Terms: clock skew is the difference between the readings of two clocks at the same instant. Clock drift is the difference in their rates. Offset is the difference between a clock and the reference time. External synchronization keeps clocks within a bound of a UTC source; internal synchronization keeps them within a bound of each other.

AlgorithmIdeaType
Cristian’s algorithmThe client asks a time server at its clock time T0, the server replies with its time TS, and the reply arrives at T1. The client sets its clock to TS + (T1 − T0)/2, assuming equal delays in both directions.External
Berkeley algorithmA master polls all machines for their clock values, averages them (ignoring far-off values) and sends each machine the adjustment it should apply, not the absolute time.Internal
Network Time Protocol (NTP)Servers are arranged in a hierarchy of strata; stratum 1 servers are connected to UTC sources and each lower stratum synchronizes with the one above. Client and server exchange timestamped messages.External

NTP offset and delay. The client sends a request at T1 (client clock); the server receives it at T2 and replies at T3 (server clock); the client receives the reply at T4 (client clock).

offset θ = [ (T2 − T1) + (T3 − T4) ] / 2
delay δ = (T4 − T1) − (T3 − T2)

Example: T1 = 100, T2 = 145, T3 = 147, T4 = 112. Then θ = [(145 − 100) + (147 − 112)]/2 = (45 + 35)/2 = 40, so the client clock is 40 units behind the server, and δ = (112 − 100) − (147 − 145) = 12 − 2 = 10.

2. Framework of a system of logical clocks

A system of logical clocks consists of a time domain T, a partially ordered set with relation <, and a logical clock C that assigns every event e a timestamp C(e) ∈ T. It must satisfy the clock consistency condition:

ei → ej ⇒ C(ei) < C(ej)

If the converse also holds, C(ei) < C(ej) ⇒ ei → ej, the system is strongly consistent.

Implementation. Each process pi keeps a local logical clock and updates it by two rules:

  • R1: how the local clock is updated when pi executes an event (send, receive or internal).
  • R2: how the clock is updated when pi receives a message, using the timestamp carried by the message.

3. Scalar time (Lamport)

The time domain is the set of non-negative integers; each process pi has one integer clock Ci.

  • R1: before executing an event, Ci := Ci + d (d > 0, normally 1).
  • R2: a message carries the timestamp Cmsg of its send event. On receipt, Ci := max(Ci, Cmsg); then execute R1; then deliver the message.

Properties: (i) consistent: ei → ej ⇒ C(ei) < C(ej); (ii) total ordering is obtained by ordering equal timestamps by process id, (h, i) < (k, j) iff h < k or (h = k and i < j); (iii) event counting: with d = 1, C(e) = the height of e in the causal graph; (iv) not strongly consistent, because C(ei) < C(ej) does not imply ei → ej.

4. Vector time

The time domain is the set of n-dimensional non-negative integer vectors; process pi keeps a vector Vi[1..n], where Vi[i] is pi’s own logical clock and Vi[j] is pi’s latest knowledge of pj’s clock.

  • R1: before executing an event, Vi[i] := Vi[i] + d.
  • R2: a message carries the vector vt of its send event. On receipt, Vi[k] := max(Vi[k], vt[k]) for 1 ≤ k ≤ n; then Vi[i] := Vi[i] + d; then deliver.

Comparison of vectors: vh ≤ vk iff vh[x] ≤ vk[x] for all x; vh < vk iff vh ≤ vk and vh[x] < vk[x] for some x; vh ∥ vk iff neither vh < vk nor vk < vh.
