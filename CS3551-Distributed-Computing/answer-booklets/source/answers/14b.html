Introduction: the agreement problems

Processes in a distributed system must often agree on a value. Three related problems are defined:

ProblemInitial valuesRequirements
Byzantine agreementOne designated process (the source or commander) has an initial value.Agreement: all non-faulty processes decide the same value. Validity: if the source is non-faulty, the common value is the source’s value. Termination: every non-faulty process decides.
ConsensusEvery process has an initial value.Agreement, validity (if all initial values are equal, that value is decided) and termination.
Interactive consistencyEvery process has an initial value.All non-faulty processes agree on the same set (vector) of values, one per process, and the entry for a non-faulty process is its own value.

1. Agreement in a failure-free system

If no process and no link fails, agreement is easy:

  • Synchronous system: every process broadcasts its value to all others in one round. After the round every process holds the same set of values and applies the same deterministic function (majority, min, max or average) to it. All decide the same value.
  • Asynchronous system: a process waits until it has received the value from every other process; because there are no failures, every message arrives eventually. It then applies the same function. Agreement is again reached.

The problem becomes hard only when processes can fail, because other processes cannot tell whether a silent process has crashed or is only slow.

2. Agreement in a synchronous message-passing system with failures

In a synchronous system computation proceeds in rounds: in a round every process sends messages, receives the messages of that round and does its local processing, within known bounds on delay and speed.

(a) Consensus with crash failures (at most f processes may crash)

Every process pi executes the following for up to f crash failures; x is the current value, initially the process’s own value.

for round = 1 to f + 1 do
  if the current value of x has not been broadcast then broadcast(x);
  yj := value (if any) received from process j in this round;
  x := min(x, yj);
output x as the consensus value.

Why it works: at most f processes crash, so among the f + 1 rounds there is at least one round in which no process crashes. In that round every non-crashed process broadcasts its current minimum and every other non-crashed process receives it, so they all hold the same x afterwards and stay equal. Hence all decide the same value. Lower bound: f + 1 rounds are necessary for f crash failures. Message complexity is O((f + 1)·n2).

(b) Byzantine agreement

A Byzantine (arbitrary) fault means a process may send wrong or conflicting messages to different processes. Result: Byzantine agreement among n processes with at most f Byzantine processes needs n ≥ 3f + 1.

Impossibility for n = 3, f = 1. A commander C sends its value to lieutenants L1 and L2, which then exchange what they received.

  • Case (a): C is correct and sends 0 to both. Faulty L2 tells L1 “C said 1”. By validity L1 must decide 0.
  • Case (b): C is faulty and sends 0 to L1 and 1 to L2. Correct L2 tells L1 “C said 1”. L1 sees exactly the same messages as in case (a), so it again decides 0.
  • In case (b), by the symmetric argument (a case where C is correct and sends 1, and L1 is the liar), L2 must decide 1. So L1 decides 0 and L2 decides 1: agreement is violated. Hence three processes cannot tolerate one Byzantine process.

Oral-messages algorithm OM(f) (Lamport, Shostak, Pease)

It works for n ≥ 3f + 1 and takes f + 1 rounds. The commander sends its value to every lieutenant, and each lieutenant relays what it received to the others, recursively.

  1. OM(0): the commander sends its value to every lieutenant; each lieutenant uses the value it receives (a default value if none arrives).
  2. OM(m), m > 0: (1) the commander sends its value to all n − 1 lieutenants. (2) Let vi be the value lieutenant i received from the commander. Lieutenant i acts as the commander in OM(m − 1) and sends vi to the other n − 2 lieutenants. (3) Lieutenant i then takes majority(v1, …, vn−1), where vj is the value it received from lieutenant j in step 2 (and vi is its own).

Example: n = 4, f = 1 (lieutenants L1, L2, L3).

CaseRound 1 (commander to L1, L2, L3)Round 2 (lieutenants exchange)Decision
Commander correct with value 1; L3 faulty1, 1, 1L1 holds (1, 1 from L2, x from L3); L2 holds (1, 1 from L1, y from L3)L1: majority(1,1,x) = 1; L2: majority(1,1,y) = 1. Agreement and validity hold.
Commander faulty, sends 0, 1, 10, 1, 1L1: (0, 1, 1); L2: (1, 0, 1); L3: (1, 0, 1)All three compute majority = 1. Agreement holds.

Complexity: f + 1 rounds; the number of messages is (n − 1)(n − 2)…(n − f − 1), that is O(nf+1), exponential in f (9 messages for n = 4, f = 1).

Phase-king algorithm: a polynomial alternative for n > 4f. It runs f + 1 phases of two rounds each; in phase k the process with id k acts as “king” and its value is adopted by processes that did not see a strong majority.
