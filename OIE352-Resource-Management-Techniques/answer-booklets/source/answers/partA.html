Linear programming

Linear programming (LP) is a mathematical technique for finding the best value (maximum or minimum) of a linear objective function subject to a set of linear constraints (equalities or inequalities) and non-negativity of the variables.

Maximize (or minimize) Z = c1x1 + c2x2 + … + cnxn subject to Σ aijxj (≤, =, ≥) bi, xj ≥ 0.

Example uses: product mix, diet, blending and resource allocation problems.

Shadow price

The shadow price of a resource is the change in the optimal value of the objective function per unit increase in the right-hand side (availability) of that resource's constraint. It is the value of the corresponding dual variable yi, and is read from the Zj row of the final simplex table under the slack variable of that constraint.

It tells the manager how much more it is worth paying for one more unit of the resource, as long as the change stays within the range of feasibility. A resource that is not fully used (positive slack) has shadow price 0.

Unbalanced to balanced transportation problem

A transportation problem is balanced when total supply = total demand. If it is not:

  • Total supply > total demand: add a dummy destination with demand equal to (supply − demand) and zero cost (zero profit for maximization) in every cell.
  • Total demand > total supply: add a dummy source with supply equal to (demand − supply) and zero cost in every cell.

The balanced problem is then solved in the usual way (VAM and MODI).

Types of integer programming problems

  1. Pure (all-integer) IPP: all the variables must be integers.
  2. Mixed IPP: only some of the variables must be integers; the others may be continuous.
  3. Zero–one (binary) IPP: every variable can take only the values 0 or 1.

Methods: Gomory's cutting-plane method and the branch and bound method.

Dynamic programming

Dynamic programming is a method of solving a multistage decision problem by breaking it into a sequence of smaller, interrelated sub-problems called stages, which are solved one by one using a recursive relation. It is based on Bellman's principle of optimality: whatever the initial state and decision, the remaining decisions must be optimal for the state that results.

Examples: allocation of limited resources among activities, shortest route and replacement problems.

Kuhn–Tucker conditions

For the problem: minimize f(X) subject to gj(X) ≤ 0, j = 1, …, m, the Kuhn–Tucker conditions are necessary conditions for X* to be a (local) optimum:

∂f/∂xi + Σj λj ∂gj/∂xi = 0 (i = 1, …, n)
λj gj = 0, gj ≤ 0, λj ≥ 0 (j = 1, …, m)

They are also sufficient when f and every gj are convex.

Sufficient conditions on the Hessian matrix

Let X0 be a stationary point, ∇f(X0) = 0, and H the Hessian matrix of second derivatives ∂2f/∂xi∂xj at X0.

Critical path

The critical path is the longest path from the start event to the end event of a project network. Its length is the minimum time in which the project can be completed. The activities on it are critical: they have zero total float, so a delay in any of them delays the whole project.

It is found by the forward and backward pass: the activities with earliest start = latest start (and earliest finish = latest finish) form the critical path.
